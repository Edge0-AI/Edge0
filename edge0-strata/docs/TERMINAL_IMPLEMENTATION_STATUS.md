# Terminal work against the 10 October 2026 implementation plan

> **Historical record (11 October 2026).** This page was written while the Terminal was being built, before Strata 0.2.0. It is kept for the record and is not kept up to date: it describes six views, source-run commands and checks that had not yet been run on target hardware. For what the Terminal does now, see [TERMINAL.md](TERMINAL.md), [TERMINAL_LAUNCH.md](TERMINAL_LAUNCH.md) and [TERMINAL_QUICKSTART.md](TERMINAL_QUICKSTART.md).

Source baseline for the original milestone: `Niko1221/Strata` at `fb58e0dbc8399662c0e47c76578c6e878b14f6cf`. Branch `feat/terminal-cli-monitor-current` merges the public `main` fetched on 11 October 2026 at `61b3fb5dd3f1e8ec09cf7e4e05208bc6d3c46406`. The plan lives at `../output/strata-terminal-implementation-plan.md` in the parent design workspace. This is a working implementation, not a qualified release.

Current-main integration checks on macOS: 706 server tests passed with 11 skipped, all 218 terminal tests passed, and the C++20 batch/stage sampler compiled with warnings as errors and passed. The imported editable Desktop app passed TypeScript checking, a production build and 116 Node tests. The broad setup suite ran 465 tests with two failures and four errors; representative CUDA build and prebuilt-download failures reproduce on a clean public-main checkout, while HIP errors need a ROCm environment absent here. Fake-engine two-replica request/slot correlation and configured card assignment are covered; native GPU builds, native per-replica batch/stage qualification, Windows/Linux install, full Desktop authority and coding harness remain open. The Desktop native shell now supports an opt-in, owner-backed single-profile Serving Start/Stop/Restart/Verify preview, a read-only six-panel Monitor, a read-only Components screen with manual host GPU probe, a reviewed Profile editor for source run config and typed serving overrides, a read-only Models screen with per-config detail and GGUF preflight, a Benchmarks screen for reviewed managed runs, saved reports, workload-checked comparisons and private Markdown export, and a native Calibration screen for reviewed measure/apply/rollback through a pollable host job and shared journal; prototype mutations and its demo monitor sampler are disabled.

Desktop calibration now saves owner-only stage/sample progress, checks an exact worker lease across fresh host processes, and accepts an operator stop request only for the active measurement job. The request is passed into engine generation and the final receipt distinguishes cancellation from success or uncertain completion. The worker does not emit raw prompts or measurements to the browser. Apply and rollback are not cancellable in flight; abrupt worker death, real engine stop latency and Windows locking remain qualification gates.

The source-run Overview now follows YASD's asymmetric two-column composition: serving, prompt/answer speed and batch pressure on the left; four selected GPUs, live requests and activity on the right. The 80 x 24 view keeps its footer; the 110 x 30 view keeps the four card rows, request queue and pipeline groups; a taller view adds reported session totals and model/engine facts. Wide views show separate bounded load and VRAM histories for each selected card, plus batch and pre-admission histories with visible ranges; replica mode keeps child batch trends separate. VRAM history uses each card's reported used/total memory, records gaps for missing or ambiguous sensors and resets with the server instance. The 80-column view keeps current memory readings without VRAM graphs. Missing newest values and batch samples older than five seconds hide their trends. The Overview also hides current batch and host-span numbers when their engine samples are older than five seconds; the detail views retain the last reading with its age. The illustrative captures were regenerated from the current renderer. These layout checks do not establish real four-card measurements.

The replica-specific follow-up maps child slots and pipeline groups into distinct global IDs, attaches replica IDs to active requests, and labels configured GPU groups in the Overview and adds a local stage label to each card only when one engine-reported stage maps there. It shows each live child engine's validated BSTAT processed/active rows per window separately, with sample age in the Serving view. Child startup logs can also report per-replica stage/layer ranges and physical cards when the child's launch visibility order matches its configured card group. Each child now also reports its validated PSTAT host-stage sample, with local stage percentages and age in the Engine view and separate R0/R1 lines in the wide Overview. Server-wide rows/window and stage timing remain unavailable in replica mode because the children have independent sample windows. These host spans include polling delay and are not GPU utilization. Illustrative 110- and 80-column four-card replica screenshots are in the transfer packet; their values are fixtures, not hardware results.
